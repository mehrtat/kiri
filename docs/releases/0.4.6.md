## Fixed and improved
- **Upgrading Kiri without restarting WSL no longer leaves the engine unable to start.** Before 0.4.5, a container or exec could leave a stuck child process of the engine's agent behind. That child kept the agent's lock and outlived it. After an upgrade, every new agent found the lock held and gave up after 8 s, and every `docker run` failed with "VM did not boot … the agent exited: exit status: 1" until WSL was restarted. The new agent now stops the processes that hold the lock and starts.
- **The engine log says why the agent stopped.** "guest stopped before connecting" now carries the agent's own message, not only its exit status.
