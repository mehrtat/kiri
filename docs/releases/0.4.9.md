## Changed
- **Kiri Linux goes on the internal drive with the most room.** Setup used to import the `kiri` distro under `%LOCALAPPDATA%\Kiri\wsl\kiri`, on the system drive. Its disk grows with every image and build, and a full drive damages it. Setup now picks, among the fixed NTFS or ReFS drives, the one with the most free space and imports Kiri Linux into `<X>:\Kiri\wsl\kiri` on it, when that drive has more room than the one `%LOCALAPPDATA%` is on. USB, SD and MMC drives, removable drives and network drives are never used, and neither is a drive whose bus cannot be read.
  - Only a new install moves anywhere: a `kiri` distro that is already registered stays where it is. An Ubuntu that setup imports stays under `%LOCALAPPDATA%\Kiri\wsl`.
  - A rebuild of a failed disk (0.4.8's `autoRebuild`, or the repair button) keeps the folder WSL has for the distro.
  - Kiri finds the disk through WSL alone, so `wsl --manage kiri --move <folder>` needs nothing else from Kiri. Quit Kiri first, so the distro is not running during the move.
- **Uninstall removes the empty `<X>:\Kiri\wsl\kiri` folders** it leaves on another drive after it unregisters the distro.
