## Fixed and improved
- **Containers start again after a network is removed, even when an exec was cut short.** An exec's process (a `docker exec`, or a healthcheck) kept a copy of every descriptor Kiri's engine had open until it started its program. If it never did, it held a removed network's DNS socket, and every container started on the next network with that subnet failed with `dns: dns bind: Address in use (os error 98)` until WSL or the VM restarted. An exec now closes all but its own streams and namespaces right away, as a container's start already did.
