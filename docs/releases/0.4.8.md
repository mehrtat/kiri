## Added
- **Unattended machines can rebuild a failed Linux disk themselves.** A new setting, off by default, does this: `"autoRebuild": true` in `%LOCALAPPDATA%\Kiri\ui.json`, or the environment variable `KIRI_AUTO_REBUILD=1`. Neither needs an administrator. With it on, when the engine cannot start because Kiri Linux's disk failed (read-only or input/output errors, `getpwnam(root) failed 5`), kiri-win removes the `kiri` distro and imports it again from its own kiri-linux.tar.gz, with no window step and no prompt. It then starts the engine, and the boot log says `engine: Linux disk rebuilt after failure: <reason>`. All images, containers, volumes and build cache on that disk are lost, so this is for build machines whose engine data can be thrown away.
  - It only runs for Kiri Linux, never for an Ubuntu of your own, only while the drive has at least 5 GB free, and at most once an hour.
- **`docker info` reports the host drive and the last rebuild:** `KiriHostDrive`, `KiriHostDriveFree`, `KiriDiskRebuiltAt` and `KiriDiskRebuildReason`.
