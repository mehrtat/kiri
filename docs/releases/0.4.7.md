## Fixed and improved
- **A full Windows drive no longer damages Kiri's Linux disk.** The kiri distro's disk (ext4.vhdx) grows on a Windows drive. When that drive filled up, the disk's writes failed: containers and the engine died, the disk went read-only, and the engine could not start again. kiri-win now checks the room on that drive every 30 s. Below 5 GB the engine starts no new containers, pulls or builds, and answers "host drive C: is full: N MB free". The window warns too.
- **The engine says when its disk failed.** When WSL answers with read-only or input/output errors (`getpwnam(root) failed 5`), the error now says "Kiri's Linux disk failed". It names the drive's free space or says how to repair or rebuild the distro, instead of "run kiri.ps1 to install it". The boot log keeps what WSL said.
- **No more core dumps of the engine on the Windows drive.** In WSL the engine writes no core when it crashes. One of these was 16 GB, written to a drive that was already full.
