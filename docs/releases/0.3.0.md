## New
- **Docker Hub images pull where Docker Hub can't be reached.** A pull of a Hub image times Hub and its mirrors, starts with the fastest and moves on to the next when one fails, keeping the layers it already has. The built-in list holds Iranian mirrors (ArvanCloud, Liara, Focker, HamDocker, IranServer, MobinHost, Kernel, docker.ir) and foreign ones (Google's mirror.gcr.io, Timeweb, DaoCloud); your own come first, and Docker's `registry-mirrors` in `daemon.json` count too. Credentials go only to Docker Hub, never to a mirror. Builds get the same mirrors for `FROM`.
- **`kiri registry mirror`** shows the order a pull tries, with each host's time; `test` also compares the digest each gives for `alpine:latest`; `add`, `rm` and `builtin on|off` change the list.
- **Registries signed by a private or company CA work.** Kiri trusts the system's certificate store (`update-ca-certificates`, the Keychain) and, per registry, `certs.d/<host>/` as Docker does: `*.crt` CAs, and a `*.cert` with its `*.key` as a client certificate.
- **`kiri registry trust HOST`** installs a registry's CA (from a file, or the one it sends once you confirm its fingerprint) and a client certificate, then checks the registry answers; `kiri registry ls` and `rm` list and remove them.
- **Linux: `kiri setup`** runs the window's first-run checklist from a terminal: `kiri setup` shows it, `kiri setup all` (or `running`, `access`, `docker`, `builds`) does the steps, and `skip`/`unskip` keep the optional ones, shared with the window.
