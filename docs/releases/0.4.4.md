## Fixed and improved
- **Windows: Kiri keeps serving `\\.\pipe\kiri` when it is stopped and started again at once.** A script that stops Kiri and starts it straight away (`Stop-Process`, then `kiri-win --background`) started the new kiri-win while Windows was still closing the old one: the new one found the pipe still held, took it for a running Kiri and quit, and a moment later no Kiri was left (docker: "open //./pipe/kiri: The system cannot find the file specified"). The new one now waits up to 15 s for the old one to go, unless a Kiri that answers its window is serving the pipe, in which case it shows that one's window as before.
