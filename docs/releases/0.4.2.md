## Fixed and improved
- **Containers start again after networks come and go.** A network's DNS server on its gateway was kept by the bridge's name while its socket held the gateway's address. When the engine missed a network's removal, the old server stayed: if that subnet came back on another bridge, every container started on it failed with `dns: dns bind: Address in use (os error 98)` until the engine restarted, and if the bridge's name came back with another subnet, its DNS kept answering on the old address. Kiri now drops such a stale server and binds the address afresh.
