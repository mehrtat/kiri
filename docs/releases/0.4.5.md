## Fixed and improved
- **The engine no longer hangs after `docker system df`, and containers and execs no longer get stuck before they run.** The engine's agent measured disk usage on a second thread, but it starts containers and execs in a way that is only safe while it has one thread. A start or an exec that came during a measurement could leave a child process waiting forever before it ran its command. A gate PC runs `docker system df -v` whenever it is idle, so these children piled up there. Until 0.4.3 one could keep a removed network's DNS port, giving "dns bind: Address in use". A `docker exec -t` whose child got stuck made the agent itself wait, so `docker info`, `stop` and every other request hung ("Kiri engine not running"). The measurement now runs in a separate process.
